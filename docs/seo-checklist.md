# SEO портфолио: инструкция и чек-лист

## Что даёт этот этап
Статический сайт можно оптимизировать без CMS и серверной базы данных. GitHub хранит исходники; поисковые роботы и сервисы превью читают опубликованный сайт. Коммит сам по себе не обновляет хостинг: нужна сборка и публикация.

Open Graph управляет превью ссылки в поддерживающих сервисах. Он не гарантирует позиции в поиске. Title и description описывают страницу, но поисковик может выбрать другой заголовок или фрагмент текста. Индексация и рост посещаемости не гарантированы.

## Выполнено
- [x] Английские title и description в соответствии с языком сайта.
- [x] Open Graph: title, description, type, url, site_name, locale, image, image:type, width, height, alt.
- [x] Twitter Card summary_large_image с заголовком, описанием и изображением.
- [x] Постоянная JPEG-картинка из первого экрана: /assets/og-mira-portfolio.jpg, 1920×1080. Это портрет из hero, а не скриншот всей страницы. Сервисы могут кадрировать изображение по-разному.
- [x] Абсолютные canonical и URL изображений на текущем публичном домене.
- [x] Отдельный статический HTML с метаданными для главной, CV и каждого существующего кейса. Метаданные доступны без JavaScript.
- [x] Главная и CV: index, follow. Черновые кейсы, включая шаблон шестого проекта: noindex, follow до заполнения.
- [x] robots.txt не закрывает обход; sitemap.xml содержит только главную и CV. Не блокировать в robots страницы с noindex: робот должен прочитать директиву.
- [x] JSON-LD ProfilePage/Person на главной, без выдуманных профилей, отзывов и рейтингов.
- [x] H1 — основной заголовок каждой страницы. H2 — разделы. Пропущенный уровень H4 в блоках Recognition, Process и FAQ исправлен на H3, визуальные размеры сохранены.
- [x] Alt превью проектов описывает название и тип дизайна. У декоративных изображений оставлен пустой alt; фоновые детали не нужно превращать в ключевые слова.
- [x] Незаданные соцсети не ведут на несуществующие страницы из футера; Email использует mailto.
- [x] Сохранены имеющиеся lazy loading изображений ниже первого экрана и размеры превью кейсов.

## Как устроена сборка
`npm run build` выполняет TypeScript, Vite и `scripts/build-seo.mjs`. Последний шаг пишет метаданные маршрутов, robots.txt и sitemap.xml в dist. Публиковать нужно весь dist, сохраняя подпапки cv и cases. Не публиковать только index.html.

Список кейсов берётся из src/data/cases.ts; при изменении структуры этого файла проверить генератор. Он рассчитывает на текущий формат slug/title. Содержимое React по-прежнему отрисовывается JavaScript: эта работа добавляет статические метаданные, но не полную предварительную генерацию контента.

## Проверка после публикации
1. Открыть исходный HTML главной и /cv/: убедиться, что title, description, canonical и og:url соответствуют странице и не дублируются.
2. Открыть прямую ссылку og:image: должен возвращаться JPEG без входа в аккаунт. Проверить превью отправкой ссылки в целевой мессенджер. Старое превью может оставаться в кеше сервиса.
3. Проверить /robots.txt и /sitemap.xml. Карта должна содержать только реальные готовые страницы и правильный домен.
4. В DOM каждой обычной страницы проверить один H1 и порядок H2/H3. На главной внутри одного H1 есть варианты строк для разных адаптивов; CSS показывает подходящий вариант.
5. Проверить неизвестный URL. Нужен HTTP 404 на уровне хостинга, а не только надпись 404. dist/404.html подготовлен, но маршрутизация и HTTP-статус зависят от платформы. Для SPA-fallback добавлен клиентский noindex; это не заменяет серверный 404.
6. Проверить мобильную версию и PageSpeed Insights; отдельно оценить LCP, INP, CLS и вес видео. Не ухудшать первый экран ради формального балла.
7. Проверить JSON-LD валидатором Schema.org. Эта разметка описывает профиль и сама по себе не обещает расширенный сниппет.

## Что остаётся сделать
- [ ] Заполнить кейсы реальными задачами, ролью, процессом, материалами и результатами. Не придумывать показатели.
- [ ] После готовности кейса заменить draft description, разрешить index в генераторе и включить URL в sitemap.
- [ ] Подтвердить факты биографии, награды, сроки и цены перед продвижением: SEO не подтверждает достоверность контента.
- [ ] Добавить настоящие адреса соцсетей в src/config/links.ts, затем при необходимости sameAs в Person.
- [ ] Подключить Search Console и Яндекс Вебмастер, подтвердить владение и отправить sitemap. Доступ к этим сервисам в этом этапе не настраивался.
- [ ] Рассмотреть полную предварительную генерацию/SSR контента, чтобы тексты и ссылки были доступны роботам без JS.
- [ ] Настроить настоящий HTTP 404 и постоянные редиректы вариантов URL на уровне выбранного хостинга.
- [ ] Оптимизировать тяжёлые медиа после замеров. Lazy loading уже есть; показатели скорости этим этапом не измерены.
- [ ] При подключении собственного домена изменить origin в scripts/build-seo.mjs, пересобрать сайт, настроить редирект старого адреса и перепроверить Search Console.
