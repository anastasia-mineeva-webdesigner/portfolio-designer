# Отдельная админка портфолио

Админка не подключена к публичному сайту. Главный React/Vite проект, `src/`, `public/`, корневые зависимости, сборка и `.openai/hosting.json` не изменены. Никаких запросов к CMS из публичного приложения нет. Кнопка «Опубликовать в CMS» меняет только SQLite этой админки. `/admin` обслуживается отдельным Node-процессом на другом порту, а не маршрутизатором существующего приложения.

## Открыть и запустить

1. Клонируйте репозиторий, переключитесь на `feat/isolated-admin`, откройте папку в VS Code через File → Open Folder.
2. Установите Node.js **24 LTS** (нужен встроенный `node:sqlite` и выполнение TypeScript начальных данных). Основной сайт по-прежнему можно собирать на Node 22.
3. В терминале VS Code, в корне репозитория:

```bash
npm ci
npm run dev
```

Это только сайт, обычно http://localhost:5173. Админка и база ему не нужны.

4. Во втором терминале:

```bash
cd admin
npm ci
```

Создайте пароль длиной от 12 символов. В bash (на Windows используйте Git Bash) введите:

```bash
read -s -r -p 'Новый пароль: ' ADMIN_SECRET
printf %s "$ADMIN_SECRET" | npm run password --silent
unset ADMIN_SECRET
```

Пароль не передаётся в аргументах процесса и не попадает в историю команд. Скопируйте выведенную строку `ADMIN_PASSWORD_HASH=…` в файл `admin/.env`. Это scrypt с индивидуальной солью, не сам пароль. Добавьте туда:

```dotenv
ADMIN_ORIGIN=http://localhost:3001
ADMIN_PORT=3001
# Необязательно локально; на сервере задайте абсолютный путь вне кода:
# ADMIN_DATA_DIR=/var/lib/portfolio-admin
```

Не добавляйте `.env` в Git. Не используйте пароль из тестов. Запустите:

```bash
npm start
```

Откройте **http://localhost:3001/admin**. Используйте именно localhost, а не 127.0.0.1: проверяется точный Origin. Сессия длится 8 часов, выход и перезапуск сервера завершают её. После 5 неверных входов с одного адреса — блокировка на 15 минут. Для смены пароля сгенерируйте новый хеш, обновите `.env`, перезапустите процесс.

## Редактирование

Выберите кейс слева. Можно менять название, slug адреса `/cases/slug/`, внешнюю ссылку, категорию, описание, роль, объём и сроки, обложку. Главы содержат название для оглавления, заголовок, текст, подпись, изображение; главы и кейсы перемещаются кнопками. Внизу страницы — контакты, соцсети и CV. Это редактор контента, оформление и анимации остаются в коде.

«Сохранить черновик» не меняет публикацию. «Предпросмотр» доступен после входа и показывает сохранённый черновик в редакционном оформлении, а не точную копию публичной страницы. «Опубликовать в CMS» требует отдельного подтверждения. «Предыдущая публикация» возвращает предыдущую опубликованную версию и заменяет черновик; действие также требует подтверждения.

Если другая вкладка сохранила данные, сервер вернёт конфликт и не затрёт её изменения. Перед обновлением страницы скопируйте свои несохранённые тексты. Предупреждение при закрытии вкладки помогает не потерять правки. Экспорт на сервере включает только сохранённые данные.

Загрузка принимает JPEG/PNG/WebP до 8 МБ, до 40 млн пикселей, проверяет декодирование и перекодирует изображение в WebP. SVG, HTML и прочие форматы запрещены. Загрузки доступны только после входа. Удаление кейса или главы удаляет запись из черновика, исходные картинки и файлы репозитория остаются. Автоматического удаления загрузок нет: старые версии и копии могут ссылаться на них.

## Данные и резервные копии

По умолчанию данные находятся в `admin/.local-data/`: `content.sqlite` (SQLite WAL) и `uploads/`. Папка исключена из Git и находится вне `dist`. На сервере обязательно задайте `ADMIN_DATA_DIR` вне каталога приложения. Новый каталог получает все 6 текущих кейсов, исходные главы, ссылки, исходный порядок; дополнительные редактируемые поля и факты заполняются значениями текущего шаблона. Повторный запуск ничего не переинициализирует.

Кнопка «Скачать копию» скачивает JSON с черновиком, текущей и предыдущей публикациями и всеми загруженными изображениями. «Восстановить копию» проверяет формат, изображения и ревизию, восстанавливает **черновик и файлы**. Текущая публикация сохраняется: проверьте предпросмотр и затем опубликуйте отдельно. UI импортирует копии до 64 МБ. Исходные картинки `/assets/…` находятся в репозитории, поэтому для переноса нужен и репозиторий.

Для полного восстановления всех трёх версий, больших библиотек и аварийного переноса используйте файловую копию всего `ADMIN_DATA_DIR`. Сначала **остановите процесс**, скопируйте папку целиком (включая SQLite WAL/SHM при наличии), запустите процесс. Не копируйте один SQLite-файл во время записи. Храните копии вне VPS и проверяйте восстановление на отдельном тестовом каталоге. Пароль и `.env` резервируйте отдельно в защищённом месте.

## Размещение в России

Рекомендуемый вариант: Linux VPS в российском регионе Timeweb Cloud, Node 24, systemd, Nginx и SQLite на одном сервере. По официальной документации доступны российские банковские карты и СБП: [способы оплаты](https://timeweb.cloud/docs/service-payments/payment-methods), [условия привязки российской карты](https://timeweb.cloud/docs/service-payments/usloviya-privyazki-karty-dlya-avtomaticheskogo-popolneniya-balansa).

Проверено 16.11.2026 по Москве: [страница тарифов](https://timeweb.cloud/services/cloud-servers) показывала московский MSK Ultra 30, 1 CPU / 2 ГБ / 30 ГБ, 3 000 ₽/месяц; это пример видимой конфигурации, не обещание самого дешёвого тарифа. Платные составляющие: VPS и диск, публичный IP согласно выбранной комплектации, ежегодное продление домена (если уже есть — второй не нужен), желательно внешние резервные копии. Итоговую цену, НДС, включённый IP и продление домена проверьте в корзине перед покупкой. Node, SQLite, Nginx и сертификат Let's Encrypt не требуют платной лицензии; отдельная управляемая БД, Supabase, Firebase, Vercel и внешняя авторизация не нужны.

Выберите российский дата-центр и отдельный тестовый поддомен, например `editor.example.ru`. Сервер и браузер не обращаются к зарубежным CDN или сервисам авторизации; шрифт админки — системный, шрифты сайта — локальные. Доступность панели хостинга и домена **с конкретного российского провайдера без VPN не проверялась**: это нужно проверить до оплаты со своего соединения; доступность из этой среды не доказывает доступность в России. Не покупайте тариф, пока не проверили панель и способ оплаты.

1. Создайте отдельного системного пользователя `portfolio-admin`, загрузите код в `/opt/portfolio`, выполните `npm ci` в `admin/`. Основной сайт переносится отдельно как готовая папка `dist/`; этот шаг не нужен для тестирования админки.
2. Создайте `/var/lib/portfolio-admin`, владельцем назначьте пользователя сервиса, права 700. Файл конфигурации `/etc/portfolio-admin.env` — права 600, чтение только сервису/root:

```dotenv
NODE_ENV=production
ADMIN_ORIGIN=https://editor.example.ru
ADMIN_PORT=3001
ADMIN_DATA_DIR=/var/lib/portfolio-admin
ADMIN_PASSWORD_HASH=сгенерированная_строка
```

3. Пример systemd unit `/etc/systemd/system/portfolio-admin.service` (проверьте путь `node`):

```ini
[Unit]
Description=Portfolio editor
After=network.target
[Service]
User=portfolio-admin
WorkingDirectory=/opt/portfolio/admin
EnvironmentFile=/etc/portfolio-admin.env
ExecStart=/usr/bin/node server.mjs
Restart=on-failure
UMask=0077
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/lib/portfolio-admin
[Install]
WantedBy=multi-user.target
```

4. Nginx на **отдельном поддомене** проксирует запросы к `127.0.0.1:3001`. Не меняйте действующий virtual host сайта. Блок для уже настроенного HTTPS:

```nginx
server {
    listen 443 ssl;
    server_name editor.example.ru;
    ssl_certificate /etc/letsencrypt/live/editor.example.ru/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/editor.example.ru/privkey.pem;
    client_max_body_size 64m;
    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }
}
```

Сначала настройте DNS, HTTP virtual host и выпустите сертификат Certbot, затем добавьте HTTPS и редирект HTTP → HTTPS. Порт 3001 не открывайте наружу. Node слушает только loopback. Secure-cookie включается при `NODE_ENV=production`; origin в этом режиме обязан быть HTTPS. Встроенный лимит входа за Nginx общий для всех посетителей (не доверяем произвольному X-Forwarded-For); для одного владельца этого достаточно. Не раздавайте `ADMIN_DATA_DIR` через Nginx. Никакие инструкции здесь автоматически не выполнялись на хостинге.

5. Проверьте `nginx -t`, включите сервис, проверьте вход, сохранение, выход и перезапуск. Проверьте резервную копию, права на файлы, автопродление сертификата. Обновляйте зависимости и ОС. При обновлении кода каталог данных не удалять.

## Подключение к публичному сайту — отдельный будущий этап

По прямому указанию владельца **не реализовано**: нет публичного CMS API, переключателя в React или скрытых обращений к БД. Сейчас публичный сайт всегда использует `src/data/cases.ts` и `src/config/links.ts`; нечего отключать для возврата к исходному контенту.

После отдельного решения о подключении потребуется адаптер только опубликованного контента, безопасная публичная раздача опубликованных изображений, явная настройка `VITE_CMS_ENABLED=false` по умолчанию, fallback к исходным данным при любой ошибке и проверка совпадения дизайна. Просто добавление переменной сейчас ничего не включит. Не публикуйте `/admin/api/content`, `/preview` или `uploads` без авторизации: там могут быть черновики.
